# SleepJiraBot

Telegram-бот для интеграции с Jira Cloud. Авторизация через OAuth 2.0, отслеживание задач, уведомления, спринт- и канбан-отчёты, автоматические JQL-отчёты по расписанию и напоминания из календаря — всё прямо из Telegram.

## Возможности

- **Jira OAuth 2.0** — безопасная авторизация с шифрованием токенов (AES-256-GCM), автоматический refresh, поддержка нескольких Atlassian-сайтов
- **Управление задачами** — просмотр, комментирование, смена статуса, назначение
- **Создание задач** — пошаговый мастер с привязкой к Epic, выбором шаблона (tap-to-copy тела), приоритетом и исполнителем; сохранение переиспользуемых шаблонов; быстрое создание одной командой
- **Мгновенное создание (`/createfast`)** — текст или фото/файл с подписью превращается в задачу Jira с вложением, выбором Epic и подтверждением. Любое обычное сообщение трактуется как шорткат `/createfast`
- **Подписки** — уведомления об изменениях задач/проектов через поллинг и подписанные вебхуки Jira (HMAC-SHA256)
- **Спринт-отчёты** — просмотр спринт-бордов и прогресса
- **Канбан-отчёты** — метрики потока на уровне доски (throughput, cycle/lead time, WIP, возраст задач, эффективность потока) с периодами 7/14/30 дней; выбор доски в проектах с несколькими бордами; учитываются пользовательские статусы готовности и блокировки из профиля
- **Отчёты по расписанию** — автоматическая отправка JQL/спринт-отчётов по cron
- **Дейли-стендапы** — быстрый обзор назначенных задач для себя или коллег + подписка на ежедневный стендап с учётом таймзоны
- **Напоминания из календаря** — подписка на iCal/ICS «секретный адрес» (Google/Outlook/Apple) через Профиль → 📅 Календарь; бот опрашивает фид, разворачивает повторяющиеся события и присылает в личку уведомления «новое», «изменено» и «начнётся через N мин» с настраиваемым временем напоминания
- **Дефолты** — персональные значения проекта, борда и типа задачи через `/defaults`
- **Админ-инструменты** — панель `/admin` (статистика, управление пользователями, рассылка, статус поллера), `/diagnose` для диагностики OAuth-скоупов/API/вебхуков и `/webhooks_resync` для сверки вебхуков Jira с локальной БД
- **Мультиязычность** — английский и русский

## Команды бота

| Команда | Описание |
|---------|----------|
| `/start`, `/menu` | Главное меню |

| `/me` | Текущий профиль |
| `/issue <KEY>` | Просмотр задачи |

| `/list [JQL]` | Поиск задач |
| `/comment <KEY> <текст>` | Добавить комментарий |
| `/transition <KEY>` | Сменить статус задачи |
| `/assign <KEY>` | Назначить задачу на себя |
| `/create` | Пошаговый мастер создания задачи |
| `/create <ПРОЕКТ> <Тип> \| <Заголовок> \| <Описание>` | Быстрое создание задачи |
| `/createfast [заголовок]` | Мгновенное создание — текст или фото/файл с подписью → задача с вложением |
| `/sprint [ПРОЕКТ] [БОРД] [СПРИНТ]` | Спринт-борд |
| `/kanban [ПРОЕКТ] [ДНИ]` | Канбан-отчёт (throughput, cycle time, WIP) |
| `/filters` | Сохранённые фильтры Jira |
| `/watch` / `/unwatch` | Подписаться/отписаться от изменений |
| `/subscriptions` | Список активных подписок |
| `/schedule <cron>` | Создать отчёт по расписанию |
| `/unschedule` / `/schedules` | Управление расписаниями |
| `/defaults` | Настроить проект, борд и тип задачи по умолчанию |
| `/lang` | Сменить язык |
| `/help` | Помощь |
| `/admin` | Админ-панель — статистика, пользователи, рассылка, статус поллера (только админ) |
| `/diagnose [user_id]` | Диагностика OAuth-скоупов, API-проб и расхождений вебхуков (только админ) |
| `/webhooks_resync [user_id]` | Сверка вебхуков Jira с локальной БД (только админ) |

> Напоминания из календаря настраиваются через меню (Профиль → 📅 Календарь), а не командой. Подписка на ежедневный стендап — в разделе Отчёты → ⏰ Daily Subscription.

## Быстрый старт

### Требования

- Go 1.25+
- MongoDB 7+
- Токен Telegram-бота ([@BotFather](https://t.me/BotFather))
- OAuth 2.0 приложение Jira Cloud ([developer.atlassian.com](https://developer.atlassian.com/console/myapps/))

### Локальный запуск

```bash
cp .env.example .env
# Заполните .env своими данными

make run
```

### Docker

```bash
cp .env.example .env
# Заполните .env своими данными

make docker-build
```

Запускает бота и MongoDB 7 через Docker Compose.

## Конфигурация

| Переменная | Обязательна | По умолчанию | Описание |
|------------|-------------|--------------|----------|
| `TELEGRAM_TOKEN` | да | — | Токен Telegram Bot API |
| `JIRA_CLIENT_ID` | да | — | Client ID приложения Jira OAuth 2.0 |
| `JIRA_CLIENT_SECRET` | да | — | Client Secret приложения Jira OAuth 2.0 |
| `ENCRYPTION_KEY` | да | — | 64 hex-символа (32 байта) для AES-256-GCM |
| `ENCRYPTION_KEY_PREVIOUS` | нет | — | Старый ключ как fallback для расшифровки при ротации ключа |
| `JIRA_REDIRECT_URI` | нет | `http://localhost:8080/callback` | URL обратного вызова OAuth |
| `JIRA_WEBHOOK_URL` | нет | — | Публичный HTTPS-эндпоинт, куда Jira шлёт события вебхуков |
| `JIRA_WEBHOOK_SECRET` | нет | — | Секрет для проверки подписи вебхуков (HMAC-SHA256) |
| `ALLOW_UNSIGNED_WEBHOOKS` | нет | `false` | Принимать неподписанные POST-вебхуки (только за сетевым ACL / proxy-auth) |
| `ADMIN_TELEGRAM_ID` | нет | — | Telegram ID пользователя с доступом к админ-командам |
| `MONGO_URI` | нет | `mongodb://localhost:27017` | Строка подключения к MongoDB |
| `MONGO_DB` | нет | `sleepjirabot` | Имя базы данных |
| `CALLBACK_ADDR` | нет | `:8080` | Адрес HTTP-сервера |
| `POLL_INTERVAL` | нет | `30s` | Интервал поллинга подписок |
| `BATCH_WINDOW` | нет | `1m` | Окно группировки уведомлений |
| `PROXY_URL` | нет | — | SOCKS5-прокси для всех исходящих соединений |
| `LOG_LEVEL` | нет | `info` | Уровень логирования (debug/info/warn/error) |

Генерация ключа шифрования:

```bash
openssl rand -hex 32
```

### Календарный фид

| Переменная | Обязательна | По умолчанию | Описание |
|------------|-------------|--------------|----------|
| `CALENDAR_POLL_INTERVAL` | нет | `5m` | Как часто перечитывается каждый ICS-фид |
| `CALENDAR_LOOKAHEAD` | нет | `24h` | Окно разворота повторяющихся событий (RRULE) |
| `CALENDAR_FETCH_TIMEOUT` | нет | `30s` | Таймаут загрузки ICS |
| `CALENDAR_DEFAULT_REMINDER_MIN` | нет | `15` | Время напоминания по умолчанию (минуты) |
| `CALENDAR_NEW_HORIZON` | нет | `1h` | Порог, при котором новое событие даёт пинг «🆕 New event» |

Поллер календаря работает в `cmd/bot`; при нескольких репликах напоминание остаётся единственным благодаря `DEDUP_REDIS_URL`.

### Микросервисы

Сервисы используют общий `.env` и обмениваются событиями через NATS JetStream (обязателен). Кросс-сервисные переменные — `NATS_URL`, `IDENTITY_SVC_URL`, `PREFERENCES_SVC_URL`, `WEBHOOK_SVC_URL`, `INTERNAL_AUTH_TOKEN`, `DEDUP_REDIS_URL`, адреса прослушивания `*_SVC_ADDR` и ключи `OTEL_*` — описаны в `.env.example`.

## Архитектура

SleepJiraBot работает как набор микросервисов с общими MongoDB и шиной событий
NATS JetStream. Монолита нет — каждая ответственность живёт ровно в одном
сервисе:

| Сервис (`cmd/`) | Отвечает за | Порт |
|-----------------|-------------|------|
| `bot` | OAuth `/callback`, веб-страницы, поллер календаря | `:8080` |
| `identity-svc` | Лизинг и обновление токенов Jira (единственный владелец refresh) | `:9080` |
| `preferences-svc` | Пользовательские настройки | `:9082` |
| `subscription-svc` | Поллинг Jira | `:8082` |
| `scheduler-svc` | Отчёты по cron | `:8083` |
| `webhook-svc` | Приём вебхуков Jira + обновление (24ч) | `:8081` |
| `telegram-svc` | Обработка апдейтов Telegram + доставка уведомлений | `:8084` |

`subscription-svc`, `scheduler-svc`, `webhook-svc` и поллер календаря в `bot`
публикуют события `NotifyRequested`; единственный отправитель в Telegram —
`telegram-svc`. Все потребители токенов Jira лизят их у `identity-svc`, поэтому
гонки обновления невозможны по построению. Каждый сервис отдаёт `/healthz` +
`/readyz` и корректно завершается по SIGINT/SIGTERM.

```
cmd/                     # По одному main.go на сервис (см. таблицу выше)
internal/
  config/                # Конфигурация через переменные окружения
  crypto/                # Шифрование токенов AES-256-GCM
  jira/                  # OAuth 2.0, callback-сервер, SiteConnector, REST-клиент
  telegram/              # Обработчики команд, меню, состояние диалогов
  poller/                # Периодический поллинг подписок
  scheduler/             # Отчёты по расписанию (cron)
  webhook/               # Обработка вебхук-событий Jira
  webhookstats/          # Удалённый сбор статистики доставки вебхуков
  calendar/              # Загрузка + парсинг ICS + разворот RRULE
  calendarpoller/        # Поллинг календарных фидов и отправка напоминаний
  daily/                 # Построение дейли-стендап-отчёта
  identity/              # Провайдер лизинга токенов + HTTP-сервер
  storage/               # MongoDB-репозитории (User, Subscription, Schedule, …)
  preferences/           # Пользовательские настройки (язык, дефолты, маппинги полей)
  notifydedup/           # Дедупликация уведомлений (in-memory или Redis)
  locale/                # Локализация (en, ru)
  format/                # Форматирование Telegram MarkdownV2
  middleware/            # Rate limiting
  proxy/                 # SOCKS5-диалер
  logger/                # Настройка Zerolog
pkg/                     # Кросс-сервисные контракты: events/v1, natsx, notifier,
                         # identityv1/client, preferencesv1/client, telemetry, health
```

`docker compose up` поднимает весь набор (плюс NATS и Redis); Mongo живёт во
внешней сети. См. [Docker-команды](#docker-команды) ниже.

## Настройка Jira-приложения

1. Перейдите на [developer.atlassian.com/console/myapps](https://developer.atlassian.com/console/myapps/)
2. Создайте новое OAuth 2.0 приложение
3. Добавьте **гранулярные** scopes Jira, которые использует бот (задачи, комментарии, вложения, проекты, приоритеты, фильтры, вебхуки и т.д.) плюс `offline_access`. **Не** добавляйте классические `read:jira-work` / `write:jira-work` / `read:jira-user` — их смешивание даёт «гибридный» токен с ошибкой *«scope does not match»*. Проверить выданный набор против требуемого можно командой `/diagnose`.
4. Укажите callback URL, совпадающий с `JIRA_REDIRECT_URI`
5. Скопируйте Client ID и Secret в `.env`
